Kubernetes concepts: pods, services, and why they exist

1 min read

Running a handful of containers by hand is manageable. Running hundreds across many machines is not: containers crash, machines fill up, and traffic needs routing to whichever copy is healthy. Kubernetes automates that work. It watches the desired state you declare and keeps reality matching it, restarting failed containers and spreading load.

The core objects, simply

  • Pods are the smallest unit: one or more containers that share storage and network and run together.
  • Deployments declare how many copies of a pod should run, and replace them when they fail or update.
  • Services give a stable address to a changing set of pods, so callers never track individual containers.
  • ConfigMaps and secrets hold settings outside the container image, so the same image runs anywhere.

Learn these four objects before touching anything advanced. Most real clusters use them for the majority of workloads.
